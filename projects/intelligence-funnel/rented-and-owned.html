One test decides everything: does it accumulate?

Not "is it useful." Useful things evaporate. The only question worth asking of any hour, any tool, any new project: does it leave something behind that the next one starts from?

The watcher — .github/workflows/watch.yml Accumulates Runs twice a day on GitHub's servers. No key, no approval, nobody awake. Appends to WATCH-FEED.md, and writes a line even when it finds nothing. This one is already right.
The posting queue — Blotato Accumulates 20 posts scheduled right now, next one today at 17:00 UTC, across TikTok, Instagram, Threads and YouTube. 3,890 credits in hand. Read live today — the record saying the queue was empty is out of date.
room-read — the situational-intelligence skill Evaporates Already built, 16 Aug, and it is the product prototype. But it answers and stops. Every run spends the thirty years and stores none of it. This is the leak.
market-read — on-demand market reads Evaporates Same shape, same leak. Read it out loud, lose it.
The adaptive funnel Open Accumulates only if answers persist and the routing gets better from them. That is a design decision, not a consequence — and it is still unmade.
A fifteenth project folder Evaporates One person, on a phone. Attention is the binding constraint, not capability.

Staying ahead is not the missing piece

The watcher already runs, twice daily, unattended. Your own file says the real regression is different: three months ago you knew about Block's Buzz before Scott did, and the system took those hours and gave back maintenance.

The measure is not a tidier repo. It is whether you are back ahead of the news and out of the upkeep.

So the trend answer is not another feed. It is that nothing new gets its own project — it attaches to a loop that already runs, or it gets logged and parked.

What to do

  1. Give room-read a memory

    Add one step: every run appends the room, the door rule, the dress read and what was current, to a single growing file. No new build, no new project — one paragraph added to a skill that already works. This is the moat, and today it is being spent and thrown away.

  2. Decide the funnel accumulates

    Before any code: answers persist, and routing improves from them. Otherwise it is a nicer form, and a nicer form is rented too.

  3. Park everything that fails the test

    One person. Anything needing daily hands does not survive — the 31-day posting run proved that once already. Keep the loops that run without you.
